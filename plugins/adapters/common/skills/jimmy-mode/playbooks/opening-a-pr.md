### Opening a PR

Use this when PR delivery is within the user's scope. Follow the repository's contribution rules and current host tools. Inspect the actual diff, exclude unrelated changes, and complete required checks. Reuse valid [verification evidence](../../../docs/verification.md); do not rerun checks merely because this is a new phase.

Write a concise title and description around the final problem, behavior, material tradeoffs, and observed validation. Use the repository template when present. Additional prose-cleanup skills and review panels are optional, triggered by a specific need rather than every PR.

Create the PR through an available forge tool or CLI, verify its actual state, and attach it when the host exposes an attachment tool. Preserve user gates for publishing, merging, and external messages. If PR creation is unavailable, deliver the local diff and state the gap. Do not invent a PR link.
